# 测试报告生成工作流
# Test Report Generation Workflow
# 版本: v1.0
# 作用: 从测试追踪数据到测试报告 Excel 的完整流程定义
# 加载策略: 各平台适配器引用此文件，在触发「测试报告生成」时加载

---

## 触发条件

- 用户说"生成测试报告" / "输出测试报告" / "总结测试结果"
- 用户上传测试追踪表并要求分析
- 用户说"测试完了，出个报告"

---

## 输入数据格式

### 方式一：测试追踪 Excel（推荐）

用户上传包含以下列的 Excel 或 CSV：

| 列 | 字段 | 说明 |
|----|------|------|
| A | 用例编号 | TC-XX-XX-XXX-X |
| B | 所属模块 | 功能模块名称 |
| C | 用例名称 | 测试用例名称 |
| D | 测试类型 | 功能/接口/性能... |
| E | 优先级 | P0/P1/P2/P3 |
| F | 执行状态 | 通过/失败/阻塞/跳过/未执行 |
| G | 实际结果 | 执行后填写（失败时必填） |
| H | 执行人 | 执行者姓名 |
| I | 执行日期 | YYYY-MM-DD |
| J | 关联缺陷ID | Bug编号（可选） |
| K | 备注 | 补充说明 |

### 方式二：对话中直接提供

用户以文本形式提供执行摘要，Skill 提取关键信息后生成报告。

### 方式三：复用模块一产物

如果用户用模块一生成了测试用例，同一 Excel 中已包含执行状态列，直接复用。

## 工作流总览

```
输入 (测试追踪 Excel / 文本)
       │
       ▼
┌──────────────────────────────────────────────────────────────────┐
│ 步骤1: 接收与解析                                                  │
├──────────────────────────────────────────────────────────────────┤
│ 1.1 读取输入                                                       │
│  ├── 若为 Excel: pandas 读取，自动识别 Sheet                       │
│  ├── 若为 CSV: pandas 读取                                         │
│  └── 若为文本: 解析关键信息                                        │
│ 1.2 识别列结构                                                     │
│  ├── 自动匹配标准列名（支持中英文别名）                              │
│  │   例如: "用例编号" / "case_id" / "ID" / "编号"                   │
│  └── 标注未识别的列                                                │
│ 1.3 提取元数据                                                     │
│  ├── 项目名称（从文件名或用户提供）                                 │
│  ├── 测试版本                                                      │
│  ├── 执行周期（最早日期 ~ 最晚日期）                                │
│  ├── 执行环境（从执行记录提取）                                     │
│  └── 执行人列表                                                    │
│ 输出: 结构化数据 + 元数据                                          │
│ 耗时: 1 分钟                                                       │
└──────────┬───────────────────────────────────────────────────────┘
           ▼
┌──────────────────────────────────────────────────────────────────┐
│ 步骤2: 数据清洗与校验                                              │
├──────────────────────────────────────────────────────────────────┤
│ 2.1 完整性检查                                                     │
│  ├── 缺失字段: 标注并提示用户                                      │
│  ├── 重复记录: 标记重复行                                          │
│  └── 空值检查: 必填字段是否有空值                                  │
│                                                                   │
│ 2.2 状态标准化                                                     │
│  ├── 映射各种写法到标准值                                          │
│  │   "pass" / "✅" / "ok" / "通过" → "通过"                       │
│  │   "fail" / "❌" / "失败" / "不通过" → "失败"                    │
│  │   "block" / "阻塞" / "blocked" → "阻塞"                        │
│  └── 标记无法映射的值                                              │
│                                                                   │
│ 2.3 合理性校验                                                     │
│  ├── 日期是否在合理范围内                                          │
│  ├── 优先级分布是否合理（P0 不应为 0）                              │
│  └── 用例编号格式是否符合规范                                      │
│                                                                   │
│ 输出: 清洗后的数据 + 数据质量报告                                  │
│ 耗时: 1 分钟                                                       │
└──────────┬───────────────────────────────────────────────────────┘
           ▼
┌──────────────────────────────────────────────────────────────────┐
│ 步骤3: 多维度统计分析                                              │
├──────────────────────────────────────────────────────────────────┤
│                                                                   │
│ 3.1 整体执行统计                                                   │
│  ├── 总用例数                                                      │
│  ├── 已执行 / 未执行（数量 + 占比）                                │
│  ├── 通过 / 失败 / 阻塞 / 跳过（数量 + 占比）                      │
│  └── 通过率                                                        │
│                                                                   │
│ 3.2 按优先级统计                                                   │
│  ├── P0: 通过率 / 失败数 / 阻塞数（P0 必须 100% 通过）              │
│  ├── P1: 通过率 / 失败数 / 阻塞数                                  │
│  ├── P2: 通过率 / 失败数 / 阻塞数                                  │
│  └── P3: 通过率 / 失败数 / 阻塞数                                  │
│                                                                   │
│ 3.3 按模块统计                                                     │
│  ├── 各模块的通过率 / 失败数 / 阻塞数                               │
│  ├── 模块用例分布                                                  │
│  └── Top 问题模块（失败率最高）                                    │
│                                                                   │
│ 3.4 按测试类型统计（引用 test-type-methods.md）                     │
│  ├── 各类型的通过率与缺陷密度                                       │
│  ├── 类型覆盖分布（雷达图数据源）                                    │
│  ├── 按类型缺陷 Top 问题                                            │
│  └── 用户侧重类型 vs 实际执行的偏差分析                              │
│                                                                   │
│ 3.5 功能覆盖度统计                                                 │
│  ├── 已测功能点数 / 总功能点数                                     │
│  ├── 需求覆盖率（如有关联需求）                                    │
│  └── 环境覆盖率                                                    │
│                                                                   │
│ 3.6 缺陷统计                                                       │
│  ├── 缺陷总数                                                      │
│  ├── 按严重程度分布: 致命/严重/一般/轻微/建议                      │
│  ├── 按模块分布: 各模块缺陷数                                      │
│  ├── 按状态: 已修复/待修复/不予修复/重复                            │
│  └── 修复率                                                        │
│                                                                   │
│ 3.7 执行效率统计                                                   │
│  ├── 执行周期（天数）                                              │
│  ├── 日均执行用例数                                                │
│  ├── 人均执行用例数                                                │
│  ├── 缺陷发现率 (缺陷/用例)                                        │
│  └── 缺陷修复周期（中位数）                                        │
│                                                                   │
│ 输出: 统计结果集                                                  │
│ 耗时: 1-2 分钟                                                     │
└──────────┬───────────────────────────────────────────────────────┘
           ▼
┌──────────────────────────────────────────────────────────────────┐
│ 步骤4: 图表生成                                                    │
├──────────────────────────────────────────────────────────────────┤
│ 引用: chart-specs.json                                            │
│                                                                   │
│ 4.1 整体执行结果饼图 (Pie)                                         │
│  └── 通过/失败/阻塞/未执行 四色分布                                │
│                                                                   │
│ 4.2 各模块执行状态堆叠柱状图 (Stacked Bar)                          │
│  └── X: 模块名  Y: 用例数  堆叠: 通过/失败/阻塞                    │
│                                                                   │
│ 4.3 测试类型覆盖雷达图 (Radar)                                     │
│  └── 轴: 功能/接口/性能/安全/兼容/UX/用户视角/回归                  │
│                                                                   │
│ 4.4 每日执行进度趋势折线图 (Line)                                   │
│  └── X: 日期  Y: 累积执行 / 累积通过 / 计划线                      │
│                                                                   │
│ 4.5 优先级执行状态堆叠柱状图 (Stacked Bar)                          │
│  └── X: P0/P1/P2/P3  Y: 用例数  堆叠: 通过/失败/其他               │
│                                                                   │
│ 4.6 缺陷严重程度分布饼图 (Pie)                                      │
│  └── 致命/严重/一般/轻微/建议（致命扇区 explode）                   │
│                                                                   │
│ 4.7 缺陷模块分布柱状图 (Bar)                                        │
│  └── X: 模块  Y: 缺陷数（降序）                                    │
│                                                                   │
│ 4.8 缺陷趋势折线图 (Line)                                           │
│  └── X: 日期  Y: 新增/关闭/累积未关闭 三条线                        │
│                                                                   │
│ 4.9 上线就绪度进度条 (Progress Bar)                                 │
│  └── 评分/100，四色阈值分段                                        │
│                                                                   │
│ 降级方案（无 matplotlib 时）:                                      │
│  ├── 饼图 → ASCII art 比例图                                       │
│  ├── 柱状图 → Unicode 水平柱状图                                    │
│  ├── 折线图 → 数据表格 + 文字趋势描述                                │
│  └── 进度条 → `████████░░ 78%` 格式                                │
│                                                                   │
│ 输出: 图表嵌入 Excel 或降级为文本                                  │
│ 耗时: 1-2 分钟                                                     │
└──────────┬───────────────────────────────────────────────────────┘
           ▼
┌──────────────────────────────────────────────────────────────────┐
│ 步骤5: 风险评估与结论                                              │
├──────────────────────────────────────────────────────────────────┤
│ 引用: risk-identification-rules.md                                │
│                                                                   │
│ 5.1 自动风险扫描                                                   │
│  ├── 逐条执行 10 条风险规则                                        │
│  ├── 标记触发的规则: 🔴高 / 🟠中 / 🟡需关注                        │
│  └── 生成风险清单                                                  │
│                                                                   │
│ 5.2 上线就绪度计算                                                 │
│  ├── 基础分 100                                                    │
│  ├── 扣分: P0未通过(-3/个) + 致命缺陷(-10/个) + ...                │
│  ├── 加分: 回归全通过(+5) + 灰度方案(+3) + 回滚方案(+3)            │
│  └── 结果: 得分/100 + 等级(A/B/C/D)                                │
│                                                                   │
│ 5.3 结论与建议                                                     │
│  ├── 功能完成度摘要                                                │
│  ├── 质量评估结论                                                  │
│  ├── 回归验证结论                                                  │
│  ├── 风险提示                                                      │
│  └── 上线建议（全量/灰度/暂缓）                                    │
│                                                                   │
│ 5.4 反问用户补充                                                   │
│  ├── 有无遗漏的已知问题？                                         │
│  ├── 上线决策是什么？                                              │
│  └── 报告是否有特殊要求？                                          │
│                                                                   │
│ 输出: 风险清单 + 上线就绪度评分 + 结论建议                         │
│ 耗时: 1-2 分钟                                                     │
└──────────┬───────────────────────────────────────────────────────┘
           ▼
┌──────────────────────────────────────────────────────────────────┐
│ 步骤6: 报告输出                                                    │
├──────────────────────────────────────────────────────────────────┤
│ 引用: excel-schema.json (test_report_workbook)                    │
│                                                                   │
│ 6.1 生成 Excel 文件                                                │
│  ├── 格式: openpyxl (降级: Markdown + CSV)                         │
│  ├── 包含: 10 个 Sheet                                            │
│  ├── 嵌入: 图表 + KPI 卡片 + 条件格式                              │
│  └── 样式: zebra striping + header 深色 + 风险色标注               │
│                                                                   │
│ 6.2 报告摘要                                                       │
│  ├── 总用例数 / 通过率                                             │
│  ├── P0 通过率 / 缺陷总数                                          │
│  ├── 风险等级 / 上线就绪度                                         │
│  └── 核心结论                                                      │
│                                                                   │
│ 耗时: 1-2 分钟                                                     │
└──────────────────────────────────────────────────────────────────┘
```

## 平台适配说明

| 平台 | 差异点 | 处理方式 |
|------|--------|---------|
| SOLO | 有 `AskUserQuestion` 工具 | 使用原生工具交互 |
| Claude Code | 无专用交互工具 | 文本形式提问 |
| Trae / Qoder | 无专用交互工具 | 对话自然语言 |
| Codex | 不可生成 Excel / 图表 | 输出 Markdown 表格 + ASCII art + CSV，提示用户本地生成 |

## 数据质量报告模板

如果在步骤2发现数据问题，输出以下格式：

```markdown
## 数据质量报告

### 问题清单
| # | 类型 | 位置 | 问题描述 | 严重程度 | 建议 |
|----|------|------|---------|---------|------|
| 1 | 缺失字段 | 第12行 | 缺少"优先级" | 低 | 可自动填充为 P2 |
| 2 | 状态异常 | 第45行 | 状态值为 "ok"，已自动标准化为 "通过" | 无 | — |
| 3 | 日期异常 | 第78行 | 执行日期为 2025-01-01，早于项目开始 | 高 | 请确认后修正 |

### 处理结果
- 自动修复: 2 条
- 需要用户确认: 1 条
- 无法处理: 0 条
```
