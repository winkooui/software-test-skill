# 测试用例生成工作流
# Test Case Generation Workflow
# 版本: v1.0
# 作用: 从 PRD 到测试用例 Excel 的完整流程定义
# 加载策略: 各平台适配器引用此文件，在触发「测试用例生成」时加载

---

## 触发条件

- 用户说"生成测试用例" / "写测试用例" / "测试用例设计"
- 用户上传 PRD/需求文档并要求测试分析
- 用户说"帮我测试 XXX 功能" / "XXX 需要怎么测"

---

## 工作流总览

```
用户输入 (PRD/需求文档)
       │
       ▼
┌──────────────────────────────────────────────────────────────────┐
│ 阶段0: 测试左移 — 需求可测试性分析                                  │
├──────────────────────────────────────────────────────────────────┤
│ 输入: PRD                                                         │
│ 处理: 按 testability-checklist.md 逐项评估                        │
│ 输出: 可测试性分析报告（评分 + 问题清单 + 改进建议）                  │
│ 门禁: 评分 ≥ 6 继续，< 6 反馈需求方                                │
│ 耗时: 2-5 分钟                                                    │
└──────────┬───────────────────────────────────────────────────────┘
           ▼
┌──────────────────────────────────────────────────────────────────┐
│ 阶段1: 需求获取与理解                                              │
├──────────────────────────────────────────────────────────────────┤
│ 输入: PRD + 可测试性报告                                           │
│ 处理: 提取产品目标、功能列表、业务流程、非功能需求、已知约束          │
│ 输出: 结构化需求摘要（内部中间产物）                                 │
│ 耗时: 2-3 分钟                                                    │
└──────────┬───────────────────────────────────────────────────────┘
           ▼
┌──────────────────────────────────────────────────────────────────┐
│ 阶段2: 产品分析与策略制定                                          │
├──────────────────────────────────────────────────────────────────┤
│ 输入: 需求摘要                                                     │
│ 处理:                                                             │
│  ├── 2.1 产品架构分析（前端/后端/数据层/外部依赖）                   │
│  ├── 2.2 确定测试边界与范围（In Scope / Out of Scope）              │
│  ├── 2.3 确定测试平台与环境                                        │
│  ├── 2.4 梳理功能树（模块→功能→子功能）                             │
│  ├── 2.5 [关键] 变更影响分析（五层追溯）                             │
│  │    └── 引用: proximity-model.md                                │
│  ├── 2.6 相近度计算 + 报表生成                                     │
│  ├── 2.7 测试环境策略（沙箱/SIT/UAT/生产）                         │
│  └── 2.8 测试数据策略设计                                          │
│ 输出: 功能树 + 相近度报表 + 环境策略 + 数据策略                     │
│ 耗时: 5-10 分钟（含相近度计算）                                     │
└──────────┬───────────────────────────────────────────────────────┘
           ▼
┌──────────────────────────────────────────────────────────────────┐
│ 阶段3: 交互式需求确认（反问用户）                                    │
├──────────────────────────────────────────────────────────────────┤
│ 展示: 功能树 + 测试范围 + 相近度报表 + 环境策略 + 数据策略           │
│                                                                   │
│ 必问问题:                                                          │
│  1. 功能树和测试范围是否准确？有无遗漏？                              │
│  2. 本次测试的重点和优先级是什么？                                  │
│  3. 是否有特殊测试场景需要覆盖？                                    │
│                                                                   │
│ 【新增】相近度专项反问:                                             │
│  4. 相近度分析报表是否遗漏了受影响的模块？                           │
│  5. 是否有需要调高相近度等级的模块？（如历史高频缺陷模块）             │
│  6. 还有哪些功能需要添加到回归范围？                                │
│  7. 历史版本中哪些模块曾因类似变更出过线上问题？                      │
│                                                                   │
│ 环境确认:                                                          │
│  8. 本次测试涉及哪些环境？各环境的操作权限？                         │
│  9. UAT 环境的生产脱敏数据是否已就绪？                              │
│ 10. 是否有环境特有的测试约束？                                      │
│                                                                   │
│ 用户画像确认:                                                      │
│ 11. 该系统的主要用户群体是？                                       │
│                                                                   │
│                                                                   │
│ 【新增】测试类型确认（检测用户意图后自动展示）:                        │
│ 12. 检测到您侧重 {类型名} 测试，已自动调整用例分布。                  │
│     测试深度确认：基础覆盖 / 中等覆盖 / 深度覆盖？                    │
│ 13. 是否需要额外补充其他类型的测试？                                 │
│ 14. 是否有特定的 {类型名} 测试工具或框架偏好？                        │
│     （如性能: JMeter/Locust；安全: Burp/ZAP）                       │
│                                                                   │
│ 条件反问（根据需求特征选择性提问）:                                  │
│  - 涉及支付/金融 → 交易精度、退款流程、对账机制                     │
│  - 涉及多角色 → 权限矩阵、数据隔离                                  │
│  - 涉及第三方 → 异常处理、超时/降级方案                             │
│  - 涉及性能 → 并发用户数、响应时间要求、SLA指标                      │
│  - 涉及安全 → 等保要求、数据加密、审计日志                           │
│                                                                   │
│ 规则: 每次反问 ≤ 4 个问题                                           │
│ 输出: 用户确认后的更新分析结果                                      │
│ 耗时: 取决于用户交互速度                                            │
└──────────┬───────────────────────────────────────────────────────┘
           ▼
┌──────────────────────────────────────────────────────────────────┐
│ 阶段4: 测试用例生成                                                │
├──────────────────────────────────────────────────────────────────┤
│ 输入: 确认后的分析结果                                             │
│                                                                   │
│ 4.1 标准业务用例                                                   │
│  ├── 引用: frameworks/test-type-methods.md                         │
│  ├── 按用户指定的测试类型调整用例分布比例                             │
│  │    检测到侧重{类型} → 该类型占比提升至 60-70%                     │
│  ├── 方法: 等价类划分 / 边界值分析 / 场景法 / 状态迁移 / 错误推测    │
│  ├── 覆盖: 功能测试 + 接口测试 + 性能测试 + 安全测试 + 兼容性测试    │
│  │        + 用户体验测试 + 用户视角测试                             │
│  └── 模板: test-case-fields.yaml                                  │
│                                                                   │
│ 4.2 回归用例（基于相近度报表）                                       │
│  ├── 引用: proximity-model.md                                     │
│  ├── 高相近 (≥4.0): 全量回归 (100%) + 交叉影响补充                  │
│  ├── 中相近 (2.0-3.9): 重点回归 (P0/P1) + 关键接口                 │
│  ├── 低相近 (1.0-1.9): 冒烟回归 (P0)                               │
│  ├── 微相近 (0.1-0.9): 极简回归                                     │
│  └── 无关 (0.0): 仅核心链路冒烟                                    │
│                                                                   │
│ 4.3 环境分层用例                                                   │
│  ├── 沙箱: 冒烟用例 + 全面用例 + 异常场景                           │
│  ├── SIT: 集成用例 + 端到端流程                                    │
│  ├── UAT: 仿真用例 + 真实数据验证                                   │
│  └── 生产: 冒烟验证 (5-10条极简)                                   │
│                                                                   │
│ 4.4 用户视角用例                                                   │
│  ├── 引用: user-perspective-checklist.md                          │
│  ├── 新手探索式: 零基础用户直觉操作                                 │
│  ├── 非预期路径: 跳过步骤/快速连击/浏览器后退/多Tab                 │
│  └── 直觉偏差: 用户理解 ≠ 系统设计                                  │
│                                                                   │
│ 4.5 关联关系                                                       │
│  ├── 前置用例: 执行前必须完成的用例                                │
│  ├── 后置用例: 执行后建议继续的用例                                │
│  └── 依赖用例: 依赖其他用例产生的数据                               │
│                                                                   │
│ 4.6 Prod 上线回归门禁用例集                                        │
│  └── 高相近 P0 全量 + 核心全链路流程                                │
│                                                                   │
│ 输出: 用例集（含所有字段）                                         │
│ 耗时: 3-8 分钟（取决于用例数量）                                    │
└──────────┬───────────────────────────────────────────────────────┘
           ▼
┌──────────────────────────────────────────────────────────────────┐
│ 阶段5: 自我审查 — 8 层检查                                         │
├──────────────────────────────────────────────────────────────────┤
│                                                                   │
│ 5.1 功能点覆盖率审查                                               │
│  ├── 方法: 遍历功能树每个节点 → 检查是否有对应用例                   │
│  └── 目标: ≥ 95%                                                  │
│                                                                   │
│ 5.2 用例串联分析（端到端流程）                                       │
│  ├── 方法: 识别核心业务流程 → 检查环节间用例链完整 + 数据流转连贯     │
│  └── 输出: 流程完整性矩阵 + 断点列表                                │
│                                                                   │
│ 5.3 测试类型覆盖审查                                               │
│  ├── 方法: 每个功能点遍历检查覆盖了几种测试类型                      │
│  └── 目标: ≥ 3 种/功能点                                           │
│                                                                   │
│ 5.4 环境覆盖完备性审查                                              │
│  ├── 方法: 检查每个环境是否都有对应用例集                            │
│  └── 目标: 计划环境 100% 覆盖                                       │
│                                                                   │
│ 5.5 用户视角用例完备性审查                                          │
│  ├── 方法: 检查每个核心模块是否有用户视角用例                        │
│  ├── 目标: ≥ 2 条/核心模块                                          │
│  └── 引用: user-perspective-checklist.md                          │
│                                                                   │
│ 5.6 回归覆盖完备性审查                                              │
│  ├── 方法: 验证相近度报表中每个功能点的回归覆盖率                    │
│  ├── 目标: 高相近 100% / 中相近 ≥ 70% / 低相近 ≥ 50%               │
│  └── 引用: proximity-model.md                                     │
│                                                                   │
│ 5.7 测试数据完备性审查                                              │
│  ├── 方法: 检查每条用例的测试数据是否明确 + 可准备                   │
│  └── 目标: 数据明确率 ≥ 90%                                         │
│                                                                   │
│ 5.8 遗漏风险识别                                                   │
│  ├── 方法: 6 维度扫描（时间/并发/数据/环境/用户/版本）               │
│  └── 输出: 遗漏风险清单 + 补充用例建议                              │
│                                                                   │
│ 评审报告: 综合 8 层结果 → 输出评审报告                              │
│ 耗时: 2-5 分钟                                                     │
└──────────┬───────────────────────────────────────────────────────┘
           ▼
┌──────────────────────────────────────────────────────────────────┐
│ 阶段6: 输出与交付                                                  │
├──────────────────────────────────────────────────────────────────┤
│                                                                   │
│ 6.1 生成 Excel 文件                                                │
│  ├── 格式: openpyxl (降级: Markdown + CSV)                         │
│  ├── 包含: 11 个 Sheet                                            │
│  └── 引用: excel-schema.json                                      │
│                                                                   │
│ 6.2 附带文档                                                       │
│  ├── 测试分析报告                                                  │
│  ├── 相近度分析报表                                                │
│  ├── 回归范围确认单                                                │
│  └── Prod 上线回归门禁检查单                                        │
│                                                                   │
│ 6.3 输出摘要                                                       │
│  ├── 总用例数 / 新增用例 / 回归用例 / 用户视角用例                   │
│  ├── 功能覆盖率 / 回归覆盖率                                       │
│  └── 质量评级                                                      │
│                                                                   │
│ 耗时: 1-3 分钟                                                     │
└──────────────────────────────────────────────────────────────────┘
```

## 平台适配说明

| 平台 | 差异点 | 处理方式 |
|------|--------|---------|
| SOLO | 有 `AskUserQuestion` / `TodoWrite` 工具 | 使用原生工具 |
| Claude Code | 无专用交互工具 | 文本形式输出问题 |
| Trae / Qoder | 无专用交互工具 | 对话自然语言 |
| Codex | 不可生成 Excel | 输出 Markdown + CSV，提示用户本地生成 |
