# 风险识别规则
# Risk Identification Rules
# 版本: v1.0
# 作用: 测试报告生成阶段自动识别风险项，计算上线就绪度评分

---

## 一、自动风险识别规则

### 规则引擎：触发条件 → 风险等级 → 风险描述

| ID | 规则名称 | 触发条件 | 等级 | 描述 | 缓解措施 |
|----|---------|---------|------|------|---------|
| R01 | P0未全通过 | P0用例通过率 < 100% | 🔴 高 | 存在核心功能未验证通过，可能影响主线业务 | 修复所有失败阻塞后重新验证 |
| R02 | 整体通过率低 | 整体通过率 < 85% | 🔴 高 | 整体质量不达标，大规模测试失败 | 分析失败根因，评估是环境问题还是代码问题 |
| R03 | 致命缺陷遗留 | 致命(Blocker)缺陷遗留数 > 0 | 🔴 高 | 已知会导致系统崩溃或核心不可用的缺陷未修复 | 必须修复后才能上线 |
| R04 | 严重缺陷遗留多 | 严重(Critical)缺陷遗留数 > 3 | 🟠 中 | 遗留多个严重问题 | 评估每个缺陷的影响面和灰度方案 |
| R05 | 阻塞用例过多 | 阻塞率 > 5% | 🟠 中 | 测试进度受阻，未覆盖区域存在未知风险 | 解除阻塞因素后补充测试 |
| R06 | 缺陷修复率低 | 缺陷修复率 < 60% | 🟠 中 | 缺陷积压，修复速度跟不上发现速度 | 评估不修复缺陷的影响，制定修复优先级 |
| R07 | 回归通过率不足 | 回归测试通过率 < 90% | 🟠 中 | 变更对已有功能的破坏未消除 | 回滚变更或修复所有回归失败 |
| R08 | 缺陷趋势上扬 | 连续3天新增缺陷数 > 关闭缺陷数 | 🟡 需关注 | 可能存在持续引入新问题 | 加强代码审查和冒烟测试 |
| R09 | 覆盖率不足 | 功能点覆盖率 < 90% | 🟡 需关注 | 部分功能未验证 | 补充测试用例 |
| R10 | P1未全通过 | P1用例通过率 < 95% | 🟡 需关注 | 重要功能未通过，影响用户满意度 | 排期修复 |

## 二、上线就绪度评分算法

### 评分公式
```
上线就绪度 = 基础分(100)
  - P0 未通过扣分
  - 致命缺陷扣分
  - 严重缺陷扣分
  - 阻塞率扣分
  - 缺陷修复率扣分
  - 回归通过率扣分
  - 补充调整项
```

### 扣分规则

| 扣分项 | 计算方法 | 扣分上限 |
|--------|---------|---------|
| P0未通过 | 每个未通过的P0用例扣 3 分 | -30 |
| 致命缺陷 | 每个遗留致命缺陷扣 10 分 | -30 |
| 严重缺陷 | 每个遗留严重缺陷扣 3 分 | -15 |
| 阻塞率 | 阻塞率每超 1% 扣 1 分 | -10 |
| 缺陷修复率 | 修复率每低于 60% 的 10% 扣 5 分 | -20 |
| 回归通过率 | 通过率每低于 90% 的 1% 扣 1 分 | -10 |

### 补充调整项
| 调整条件 | 调整值 |
|---------|--------|
| 所有高相近功能回归100%通过 | +5 |
| 已制定灰度上线方案 | +3 |
| 已制定回滚方案 | +3 |
| 有历史类似变更导致事故 | -5 |
| 外部依赖不可控（如第三方接口不稳定） | -5 |

### 评分分级

| 评分 | 等级 | 上线建议 |
|------|------|---------|
| ≥ 90 | 🟢 A | 可以上线，建议全量 |
| 75 - 89 | 🟡 B | 有条件通过，建议灰度发布 |
| 60 - 74 | 🟠 C | 不建议上线，需修复关键问题 |
| < 60 | 🔴 D | 禁止上线，存在严重风险 |

## 三、缺陷严重程度定义

| 等级 | 名称 | 定义 | 示例 |
|------|------|------|------|
| Blocker | 致命 | 导致系统崩溃、核心流程完全不可用 | 支付接口 100% 超时、数据库宕机 |
| Critical | 严重 | 核心功能不可用但系统仍可运行 | 支付成功但订单状态未更新 |
| Major | 一般 | 功能可用但有明显缺陷 | 页面显示错误但不影响核心流程 |
| Minor | 轻微 | 不影响功能使用的小问题 | UI 文案错误、对齐偏差 |
| Trivial | 建议 | 优化建议，非缺陷 | 交互可改进点 |

## 五、使用说明

1. 测试报告生成的步骤5（风险评估）阶段，按以上规则逐条检查
2. 每条规则触发后，自动填入风险报告模板
3. 如果用户提供了额外信息（如灰度方案），可加上补充调整项
4. 最终输出上线就绪度评分 + 明确的上线建议
